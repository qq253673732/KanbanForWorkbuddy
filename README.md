# KanbanForWorkbuddy

本机运行的任务看板工具。把需要 AI 执行的工作按卡片登记，由内置调度器排队领取并执行；执行完成后进入待审核状态，由人工验收。

界面为单页 Web 应用，访问 `http://127.0.0.1:8770`，无需额外安装或配置前端。

---

## 用途

| 常规做法 | 本工具 |
| --- | --- |
| 需在对话中持续等待任务执行完成 | 卡片提交后由调度器接管，可离开页面，稍后查看结果 |
| 一次只能执行一个任务 | 支持并行执行，并发数可配置（1–8） |
| 任务分散在多轮对话中，缺少统一记录 | 每张卡片对应一项任务，当前进度与执行结果均记录在卡片内 |
| 返工意见散落在对话中，缺少上下文 | 打回时填写的意见写入卡片，重新执行时随卡片一起提交 |
| 执行过程不可见，无法确认实际改动 | 保留完整执行日志，包括每一步工具调用 |
| 执行中断无反馈 | 执行失败或受阻的卡片转入「需介入」，等待人工处理 |

核心机制：任务由调度器排队领取执行，验收环节始终由人工完成。

---

## 快速开始

**前置条件**：本机已安装 [WorkBuddy](https://www.workbuddy.cn)（依赖其命令行能力）与 Python 3。

```bash
git clone <本仓库地址>
cd KanbanForWorkbuddy
python serve.py                 # 默认端口 8770；端口被占用时可指定，如 python serve.py 9000
```

终端输出 `Serving on http://127.0.0.1:8770` 后，用浏览器访问该地址。

**首次使用需创建一个项目**（右上角「项目」下拉 → 「＋ 新建项目…」）：

1. 填写项目名称，例如 `eshop`
2. 选择**项目根目录**：该目录决定 AI 的读写范围，应指向实际需要修改的项目文件夹
3. 选择卡片目录位置：项目自身的 `task/` 目录，或统一存放于看板目录下
4. 点击「创建并切换」

目录结构由程序自动创建，无需手工建立。

> 说明：命令行工具路径、项目绝对路径等信息保存在根目录的 `config.json` 中。该文件不纳入版本库（仓库内仅保留脱敏模板），在新环境中首次运行 `serve.py` 时会自动从模板生成。

## 界面说明

### 顶部控件

| 控件 | 功能 |
| --- | --- |
| **+ 新建卡片** | 新建任务卡 |
| **项目** 下拉 | 切换当前项目；卡片、附件与 AI 读写范围随之切换 |
| **轮询：开/关** | 关闭后调度器不再领取新卡片，已在执行的任务不受影响 |
| **刷新看板** | 手动刷新；页面本身会周期性自动刷新 |
| **模型** 下拉 | 设置全局默认模型；单张卡片可单独指定 |
| **同时任务数** | 允许并行执行的任务数量（1–8，默认 3） |
| **立即执行一轮** | 跳过轮询周期，立即领取一批卡片开始执行 |

### 六列状态

卡片不设状态按钮，所在列即为其当前状态。调度器按以下规则流转：

| 列 | 含义 | 人工操作 |
| --- | --- | --- |
| **0-待确认** | 草稿状态，调度器不会领取 | 确认后点击「开始」提交 |
| **1-待开始** | 已排队，等待调度器领取 | 无需操作 |
| **2-进行中** | AI 正在执行 | 可查看实时输出 |
| **3-待审核** | 执行完成，等待验收 | **验收**（必须由人工完成） |
| **4-已发布** | 验收通过，终态 | 作为记录保留 |
| **5-需介入** | 执行失败、超时，或 AI 报告受阻 | 排查原因，决定重新排队或修改需求 |

## 任务卡的使用流程

**1. 新建卡片** —— 点击「+ 新建卡片」，填写以下字段：

- **标题**：简要说明任务内容
- **优先级**：高 / 中 / 低；同等条件下优先级高的先执行
- **模型**：留空则使用全局默认模型；特殊任务可单独指定
- **需求**：**AI 的唯一执行依据**，需描述清楚。支持 Ctrl+V 粘贴截图或拖入图片

点击「开始」直接进入「待开始」队列；不确定时可点击「保存草稿」存入「待确认」，编辑完善后再开始。

**2. 排队执行** —— 卡片进入「待开始」后，调度器按优先级自动领取，无需手动触发，保持轮询开启即可。

**3. 查看执行过程** —— 「进行中」的卡片显示「AI 实时反馈」面板，包含模型输出与工具调用记录。关闭页面不影响执行。

**4. 验收** —— 执行完成后卡片进入「待审核」，可在卡片内查看「执行结果」：

- 通过 → 点击「审核通过」，进入「已发布」
- 不通过 → 点击「打回重做」，**必须填写处理意见**（未填写时不允许提交，避免重新执行时缺少依据）。卡片返回「待开始」重新排队，重新执行时携带该意见与上一次的执行结果，次数不限
- 执行异常 → 卡片转入「需介入」，处理后点击「退回待开始」重新排队

**5. 查阅记录** —— 任意卡片均可点击「AI 执行日志」查看完整执行过程。

## 其他能力

- **并行执行**：可通过「同时任务数」设置并行数量；各任务相互独立
- **暂停领取**：关闭「轮询」即可停止领取新任务，不影响正在执行的任务
- **图片支持**：需求字段支持粘贴或拖入图片，适用于界面截图、报错信息等
- **附件随卡片迁移**：卡片内保存图片的相对路径，整个 `task/` 目录迁移后引用关系保持不变
- **卡片为普通 Markdown 文件**：可用任意编辑器直接编辑，也可独立迁移或纳入版本管理

## 常见问题

**页面无法打开或端口被占用** —— 指定其他端口启动，例如 `python serve.py 9000`。

**卡片停留在「待开始」未被领取** —— 检查轮询是否已关闭，或并发数是否已满；可点击「立即执行一轮」手动触发。

**提示找不到命令行工具** —— WorkBuddy 升级后安装路径可能发生变化。打开根目录的 `config.json`，更新 `cli_path` 后重启 `serve.py`。

**执行中途停止** —— 打开该卡片的「AI 执行日志」确认中断位置；无法继续时点击「退回待开始」重新排队。

**执行耗时较长** —— 任务需要实际读写文件，耗时通常以分钟计。如需加快整体进度，可提高并行数。

├─ serve.py              HTTP 服务与调度器，启动入口
