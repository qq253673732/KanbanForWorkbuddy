# KanbanForWorkbuddy · 把活派给 AI，然后等它来交卷

一个跑在你本机上的**任务看板**：想让 AI 做的事写成一张卡片投进去，调度器自己排队领活、自己干活，干完把卡片推到「待审核」等你验收；不满意写下意见打回，它会带着上下文重做。

浏览器打开 `http://127.0.0.1:8770` 就是全部操作界面，没有别的要裝、要配。

---

## 它解决什么麻烦

| 以前 | 现在 |
| --- | --- |
| 要让 AI 做事就得守在对话框边上，它跑多久你等多久 | 卡片投进去就不用管了，去干别的，回来看结果 |
| 一次只能聊一个任务，第二个任务得排着队等你 | 想跑几个跑几个（1–8 个并行），谁先跑完谁先回来 |
| 交代过的事散在各条聊天记录里，做没做、做成啥样全靠回忆 | 一张卡就是一件事，走到哪一步一眼看见，卡片本身就是留档 |
| 返工要说的话在聊天里翻半天，AI 还常常忘了前情 | 打回时写的意见就附在卡片上，AI 重做时一定看得到 |
| AI 说「做完了」，到底跑没跑、动了哪些文件不清楚 | 执行过程全程可看，做完写的每一行都在卡片里 |
| 干到一半卡住了没人知道 | 自己挪到「需介入」，等你处置，不会假装成功 |

一句话：**把「人盯着 AI 干活」变成「AI 排队干活，人来验收」**。

## 三分钟开始

**前提**：本机装了 [WorkBuddy](https://www.workbuddy.cn)（用到它的命令行能力）和 Python 3。

```bash
git clone <本仓库地址>      # 或者直接下载解压
cd KanbanForWorkbuddy
python serve.py             # 端口被占用了就换一个：python serve.py 9000
```

看到 `Serving on http://127.0.0.1:8770` 就起来了，浏览器访问这个地址。

**第一次进来，先建一个项目**（右上角「项目」下拉 →「＋ 新建项目…」）：

1. 起个名字，比如 `eshop`
2. 选**项目根目录** —— 这是 AI 能读写的范围，选你要它动手的那个项目文件夹
3. 选卡片放哪：项目自己的 `task/` 目录，或统一收在看板下
4. 点「创建并切换」

目录由它自己去建，不用你手动建。然后就可以投第一张卡了。

> 顺带一提：命令行工具路径、项目绝对路径这些都在根目录的 `config.json` 里，
> **这个文件不会上传**（仓库只放一份空模板），换机器重新跑一次 `serve.py` 就会出现。

## 看板上有什么

顶部一排就够了：

| 控件 | 干什么 |
| --- | --- |
| **＋ 新建卡片** | 投一张新任务卡 |
| **项目** 下拉 | 切换当前在哪个项目干活，卡片、附图、AI 的读写范围跟着一起变 |
| **轮询：开/关** | 关掉 = 「先别动」，已经在跑的不打断，但不再领新活 |
| **立即执行一轮** | 不等轮询周期，马上领一批卡开工 |
| **同时任务数** | 允许并行几个任务（1–8，默认 3） |
| **刷新看板** | 手动刷一次（平时会自动刷新） |

### 六根柱子 = 六种状态

卡片没有「状态」按钮，它在哪根柱子里就是什么状态：

| 柱子 | 意思 | 你要做的 |
| --- | --- | --- |
| **0-待确认** | 草稿箱。AI 永远不会自己跑这里的卡 | 想清楚了点「开始」投出去 |
| **1-待开始** | 排队中，等调度器领 | 不用管 |
| **2-进行中** | AI 正在干活 | 可以看它实时在干什么 |
| **3-待审核** | AI 交卷了，等你点头 | **验收**（这一步永远留给人） |
| **4-已发布** | 通过了，终态 | 留着当存档 |
| **5-需介入** | 跑挂了 / 超了时 / AI 自己报告卡住了 | 看看怎么了，决定重跑还是改需求 |

## 一张卡的完整一生

**1. 写卡** —— 点「＋ 新建卡片」，填四样：

- **标题**：一句话说清要干什么
- **优先级**：高 / 中 / 低（同样条件下先跑高优先级的）
- **模型**：留空就跟默认值；这张卡特别难可以单独指定
- **需求**：**这是 AI 唯一的执行依据**，写清楚点。可以直接 Ctrl+V 粘贴截图、拖图进来

不确定就先点「保存草稿」落进「待确认」，改到满意再点「开始」。

**2. 排队开工** —— 点「开始」后卡片进「待开始」，调度器按优先级自动领。不用手动催，轮询开着就行。

**3. 盯着或放手** ——「进行中」的卡片上有个 **AI 实时反馈** 面板，它在想什么、调了什么工具、写了什么，逐字滚屏。不想盯就关掉页面，回来还在那儿跑。

**4. 验收** —— 干完自己跳到「待审核」，翻它的「执行结果」：

- 满意 → **审核通过**，进「已发布」
- 不满意 → **打回重做**，在上面写明意见（不写不让打回，免得 AI 不知道改哪）。它会带着你的意见和上次的结果重跑，次数不受限
- 跑挂了 → 卡片自己落到「需介入」，处理完点「退回待开始」重排一次

**5. 留档** —— 任何一张卡都能点「AI 执行日志」回看完整过程（它每一步都记着），做完一个月的任务也能查当时到底干了什么。

## 几个用顺手了会喜欢的细节

- **并行干活**：同时任务数拉到 3–4 个，睡前甩一批卡进去，早上来验收。每条任务各跑各的，互不串台
- **想让它停手就关轮询**：一个按钮的事，正在跑的不打断
- **需求里直接贴图**：界面截图、报错弹窗往里一粘，比写一百字清楚
- **附图跟着卡片走**：卡片里存的是相对路径，整个 `task/` 目录拷到别的机器、换个盘，图和卡还对得上
- **卡片是普通 Markdown 文件**：不在页面上也能直接用编辑器打开改，搬走、入库都不耽误

## 常见问题

**打不开页面 / 端口被占** —— 换个端口：`python serve.py 9000`。

**卡片一直是「待开始」没人领** —— 多半是轮询关了（顶部按钮看一眼），或者槽位占满了；点「立即执行一轮」试试。

**AI 跑起来说找不到命令行工具** —— WorkBuddy 升级后安装路径可能变了，打开根目录的 `config.json`，把 `cli_path` 改成新路径，重启 `serve.py`。

**AI 干到一半不动了** —— 打开那张卡的「AI 执行日志」看它卡在哪一步；解决不了就点「退回待开始」重来。

**任务跑得慢** —— 任务本来就是分钟级的（它在真刀真枪改文件），慢是正常的。着急就多开几个并行。

## 目录里都是什么

```
KanbanForWorkbuddy/
├─ serve.py              启动它就行，别的没了
├─ README.md             你正在看的这个
├─ docs/开发说明.md       给改代码的人看的：实现细节、接口、已知边界
├─ automation/           AI 执行时用的指令模板
├─ example/tasks/        卡片格式样板，忘了怎么写就翻一下
├─ config.json           本机配置（项目路径等），不上传
└─ runtime/              运行产生的数据：执行日志、调度状态
```

改代码、查接口、想知道「为什么这么设计」→ 看 `docs/开发说明.md`。
